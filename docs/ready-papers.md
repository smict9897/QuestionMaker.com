# Ready Papers

Library `/ready-papers`, authenticated editor `/ready-papers/[id]`, ADMIN upload/publish/presets `/admin/ready-papers`. Exactly BOARD and SCHOOL categories. Source/grade/subject/year provenance remains in the library record and studio, even when users cover publication text. Administrators must have redistribution rights.

Uses existing Setting JSON records (prefix `readypaper:v1:`), existing Vercel public Blob token; no DB migration or AI API credentials. Admin source file limit 3 MB (server action request constraints), PDF magic/MIME checks, browser renderer limit 20 pages; choose up to 10 whole pages, in selection order with reorder controls. Upload does not parse/enforce page count server-side; admin should verify before publishing. Public Blob URLs are public, including unpublished uploads: this is NOT confidential storage or paid-PDF access protection.

Every page supports crop, white cover boxes, added text, manual angle adjustment, quarter rotation, grayscale illumination normalization/BW, conservative outer-white-margin suggestions, original comparison, undo/redo/reset. Rotation clears overlays because coordinates change (undo restores them). No question OCR, auto perspective detection, book dewarp, automatic publication-text removal, or true editable Word reconstruction. White covers are raster print edits, NOT secure source redaction. Preserve time/marks by reviewing the preview. Render cap 2400px long edge (~205 dpi for A4), not upscaling lost source detail. Header is rendered above content only on first selected page, without overlapping questions. A4 print/Save PDF uses browser print; review browser margins/scale.

User drafts are explicit IndexedDB saves on the same browser, keyed by user+paper; not server-synced. Admin presets are shared; original PDF never modified. Local rendering has no external AI calls. Locally vendored PDF.js 3.11.174 is the existing dependency, with license; eval disabled for known legacy PDF.js eval vulnerability mitigation. Upgrade PDF.js as a separate maintained dependency task; do not enable eval.

No new Ready Papers price was approved. This release does not deduct balance/package or alter the existing paid question-builder enforcement. Ready studio is login-gated but unmetered; agree pricing and implement a server entitlement gate before treating it as a paid product. Nothing claims paid original-PDF protection.

Validation: 226 automated tests (including admin upload/preset denial, schema/storage validation, cleaning, publication filters); TypeScript and production Next build passed using dummy DB URL/no-engine Prisma generation because binaries.prisma.sh is unavailable in sandbox. Browser harness with real PDF.js, React editor and synthetic two-page PDF passed selection, clean mode, draft save, first-only header, preview, mobile 390px no horizontal overflow and two-page A4 PDF output. Harness mocks Next links/server action: it does not validate live DB/Blob/auth. Real admin upload, user OAuth, physical printer and production storage require authenticated deployment smoke testing. No sample copyrighted source papers are seeded.

## JSC/SSC/HSC selectors
Ready Papers now uses only JSC → NCTB Class 8, SSC → Class 9, HSC → Class 11-12. Exact subject names are taken from `lib/nctb-data.ts`, not a separate invented list. Other site question builders are unchanged. Shared dependent selects reset the subject on class change; the upload requires a class and its matching subject, validated server-side before storage. The public library uses the same catalog even when no PDFs exist. Historical grade labels (Class 8/9/10/11-12) are normalized only for library filtering, with no DB rewrite; unsupported grade records remain in admin management, but not the JSC/SSC/HSC library. Existing presets and publish toggles remain available for legacy records; metadata changes must use a valid new pair. No chapter selector.

## Upload storage configuration / separate parts
This project must have its own **public** Vercel Blob store, per the owner's explicit choice; do not attach Saifulsir.com's shared Blob token. In Vercel, open `question-maker-com-g6ec` → Storage → create a Blob store (or create via team Storage then connect this project), choose Public access, and connect Production/Preview environments. Confirm Vercel adds `BLOB_READ_WRITE_TOKEN`, then redeploy. UI wording can vary in the dashboard. Never paste the token in chat or commit it. The available connector cannot create Blob stores, so this dashboard step requires the owner. Store existence / live upload is not validated until that is done.

Admin UI shows a setup notice and disables uploads if the server has no token. The action independently checks config; validation, storage-provider and database failures have separate safe messages. Raw provider errors/secrets are never sent to the client. Token presence is not proof of valid storage credentials or quota. Post-persistence cache refresh failure is treated as success to avoid prompting a duplicate upload. Orphan Blob cleanup is attempted on failed DB write.

Multiple parts already use independent UUID records and Blob paths, even for the same class/subject/title. Title each file Part 1, Part 2, etc. Each file remains <=3,000,000 bytes and <=20 rendered pages. Parts are separate library entries, not automatically concatenated or numerically ordered, and are selected/edited separately. No automatic splitting. Regression tests verify two same-subject uploads never reuse IDs, DB keys or paths.
