# Ready Papers

Library `/ready-papers`, authenticated editor `/ready-papers/[id]`, ADMIN upload/publish/presets `/admin/ready-papers`. Exactly BOARD and SCHOOL categories. Source/grade/subject/year provenance remains in the library record and studio, even when users cover publication text. Administrators must have redistribution rights.

Uses existing Setting JSON records (prefix `readypaper:v1:`), existing Vercel public Blob token; no DB migration or AI API credentials. Admin source file limit 3 MB (server action request constraints), PDF magic/MIME checks, browser renderer limit 20 pages; choose up to 10 whole pages, in selection order with reorder controls. Upload does not parse/enforce page count server-side; admin should verify before publishing. Public Blob URLs are public, including unpublished uploads: this is NOT confidential storage or paid-PDF access protection.

Every page supports crop, white cover boxes, added text, manual angle adjustment, quarter rotation, grayscale illumination normalization/BW, conservative outer-white-margin suggestions, original comparison, undo/redo/reset. Rotation clears overlays because coordinates change (undo restores them). No question OCR, auto perspective detection, book dewarp, automatic publication-text removal, or true editable Word reconstruction. White covers are raster print edits, NOT secure source redaction. Preserve time/marks by reviewing the preview. Render cap 2400px long edge (~205 dpi for A4), not upscaling lost source detail. Header is rendered above content only on first selected page, without overlapping questions. A4 print/Save PDF uses browser print; review browser margins/scale.

User drafts are explicit IndexedDB saves on the same browser, keyed by user+paper; not server-synced. Admin presets are shared; original PDF never modified. Local rendering has no external AI calls. Locally vendored PDF.js 3.11.174 is the existing dependency, with license; eval disabled for known legacy PDF.js eval vulnerability mitigation. Upgrade PDF.js as a separate maintained dependency task; do not enable eval.

No new Ready Papers price was approved. This release does not deduct balance/package or alter the existing paid question-builder enforcement. Ready studio is login-gated but unmetered; agree pricing and implement a server entitlement gate before treating it as a paid product. Nothing claims paid original-PDF protection.

Validation: 226 automated tests (including admin upload/preset denial, schema/storage validation, cleaning, publication filters); TypeScript and production Next build passed using dummy DB URL/no-engine Prisma generation because binaries.prisma.sh is unavailable in sandbox. Browser harness with real PDF.js, React editor and synthetic two-page PDF passed selection, clean mode, draft save, first-only header, preview, mobile 390px no horizontal overflow and two-page A4 PDF output. Harness mocks Next links/server action: it does not validate live DB/Blob/auth. Real admin upload, user OAuth, physical printer and production storage require authenticated deployment smoke testing. No sample copyrighted source papers are seeded.

## Upload storage configuration / separate parts
This project must have its own **public** Vercel Blob store, per the owner's explicit choice; do not attach Saifulsir.com's shared Blob token. In Vercel, open `question-maker-com-g6ec` → Storage → create a Blob store (or create via team Storage then connect this project), choose Public access, and connect Production/Preview environments. Confirm Vercel adds `BLOB_READ_WRITE_TOKEN`, then redeploy. UI wording can vary in the dashboard. Never paste the token in chat or commit it. The available connector cannot create Blob stores, so this dashboard step requires the owner. Store existence / live upload is not validated until that is done.

Admin UI shows a setup notice and disables uploads if the server has no token. The action independently checks config; validation, storage-provider and database failures have separate safe messages. Raw provider errors/secrets are never sent to the client. Token presence is not proof of valid storage credentials or quota. Post-persistence cache refresh failure is treated as success to avoid prompting a duplicate upload. Orphan Blob cleanup is attempted on failed DB write.

Multiple parts already use independent UUID records and Blob paths, even for the same class/subject/title. Title each file Part 1, Part 2, etc. Each file remains <=3,000,000 bytes and <=20 rendered pages. Parts are separate library entries, not automatically concatenated or numerically ordered, and are selected/edited separately. No automatic splitting. Regression tests verify two same-subject uploads never reuse IDs, DB keys or paths.

## Optional light-blue watermark reduction
Per-page `blueWatermark` strength (0–1, default 0 for existing drafts/presets) runs on fresh raster pixels **before** grayscale/BW. Conservative light-blue/cyan selection fades matching pixels toward white; dark/neutral ink and other hues are not targeted. It can also remove legitimate light-blue diagrams/text. No semantic distinction between watermark and colored content, no PDF-object deletion, no recovery of obscured text and no guarantee of total removal. Original comparison, undo/redo/reset, local drafts, admin shared presets and print rendering use the same existing edit pipeline. Only use on documents with modification rights. Never enable globally or silently on all pages.

Supplied 9-page ICT PDF was tested locally on page 2 using a white-background raster. At full strength 74,065 pixels changed at 2x raster scale. Visual review showed the large blue lettering substantially reduced, but gray outlines and red/gray marks remain. Not a claim of complete removal or proof every question is intact. A review PNG is outside the repository; the source PDF is not seeded, published or uploaded to storage. Browser PDF.js rendering may differ from this local MuPDF sample; users must review the actual studio print preview.

## MCQ answer assistant (first release)
The studio has a collapsible MCQ assistant. In admin preset mode, select original question page, source answer-key page, test label and expected question count; compare both original raster previews. Optional PDF.js source-page text-layer extraction is **not OCR**. Legacy Bengali encodings are not repaired automatically. Copy only the chosen test's numbered answers into the answer input (never an entire multi-test page). K/L/M/N mapping to ক/খ/গ/ঘ is explicit and must be checked against the source. Missing, star-marked and duplicate answers stay unresolved (`?`). Admins can correct each choice, save drafts, reopen/edit and revoke approval. Every edit clears the local confirmation checkbox. Approved keys cannot contain unresolved entries. Admins must check count/numbering and source themselves: schema validation is not factual verification.

Keys are separate Setting records `readyanswers:v1:<paper UUID>:<original question page>`, not part of editable paper metadata. Only admins can mutate; users only receive approved keys. Existing metadata/preset writes never overwrite answer records. Link is by original PDF page, not selection order. This first release supports one key per original question page; a test spanning several pages or two tests on one page requires future multi-page/test identifiers. Source page bounds are schema/UI validated up to 40, not server re-parsed from the PDF. Curated source integrity remains the admin's responsibility.

Preview can show questions, blank MCQ answer sheets, or approved answer keys. Sheets follow selected question-page order and split at 25 questions per A4 sheet (up to100 questions/key). Missing approved keys show a warning rather than invented answers or assumed counts. Original embedded answer tables are still part of question images: crop/mask them before printing a question-only paper. No auto question/answer region detection. There is no automatic answer-page exclusion. No OCR provider, model-test auto-matching, AI grading, Word reconstruction, automatic answer verification or practice-question generator in this release.

AI explanation button is ADMIN-only to avoid opening unpriced provider spending to all users. It accepts explicitly entered, checked Unicode question/options text; does not send source PDF/images or raw extracted text automatically. Fixed DeepSeek text model, 4,000 character input, 1,200 output tokens, timeout, one request/30sec/admin via DB conditional update. Returned text is rendered as plain unverified draft and never updates/approves answer keys. Existing DeepSeek key is used. Vision/OCR support is not assumed. Sandbox cannot access api.deepseek.com, so live AI quality/availability/cost remains unverified; provider smoke testing requires deployment. Ordinary users can print approved keys/blank sheets but have no AI generation button.

PDF browser/preset bound increased from20 to40 pages for the supplied21-page sample; upload file size remains3MB, selected question-page limit10. Larger files still need splitting; 40-page high-resolution raster loading can be memory-heavy on mobile. No supplied copyrighted PDF or extracted key is seeded/uploaded. Unit/schema/auth/parser/print markup tests and local build are not authenticated live upload/physical print tests.

Image and selection are separate accessible targets; image opens a native modal dialog in the browser top layer, with fit/1–4x zoom, scrolling and page selection without closing. The native dialog supports Escape/focus containment; body scroll is restored on close. Canvas fullscreen is a read-only snapshot: editing remains on the normal canvas, not inside the viewer.

Print CSS removes wrappers/zoom so the actual210x297mm sheet layout and pagination remain unchanged. Mobile bottom padding reserves room for the fixed global nav/safe area. The thumbnail/canvas fullscreen dialog does not contain the custom print header; use print preview for complete output.

## Shared Smart/Dynamic headers in Ready Papers
Header type now offers legacy simple, Smart/Dynamic (existing HeaderManager), or none. The manager uses the same authenticated user-owned saved-template actions as the question builder, with no new header API or admin exception. Existing saved headers can be chosen/edited/created. Preview and print use existing HeaderPreview/currentHeader; shared header-only CSS is factored out of paper.css, avoiding importing unrelated paper-builder print/page layout styles.

Only the first selected question sheet gets the chosen header; reorder moves it to the new first sheet. Blank/answer sheets keep their own answer-sheet headings. ## Question placement inside A4 (not screen zoom)
Question preview now offers per-original-page Auto Fit/Reset, size40–100% of the maximum aspect-preserving fit, horizontal/vertical alignment in remaining space, and explicit drag-edit toggle. A4 padding and first-page header remain fixed; images are contained in the flex area below the header. Position/scale lives in the existing PageEdit schema with backwards-compatible defaults, so local drafts/admin image presets retain it. The original raster and source PDF remain unchanged. Source crop/clean/cover edits are separate and still require re-generating preview; placement edits update preview directly.

Auto Fit resets to the largest safe contain-fit, horizontally centered/top-aligned. It does not remove whitespace inside source images, stretch to fill both axes, OCR/reflow text, or zoom beyond margins. Crop unnecessary source whitespace first. When an axis has no spare space, drag/alignment on that axis does nothing. Mobile scrolling stays native unless drag-edit is explicitly enabled. Print uses the same object-fit/object-position/scale as preview; only outer screen zoom is reset for print. Blank/approved answer sheets are unaffected.

### Touch pinch and mouse wheel placement
With placement editing enabled, the question content container captures up to two pointers: one pointer pans in available slack; two pointers scale by distance ratio. Pointer-count transitions rebase the gesture to prevent jumps; up/cancel/lost-capture and mode/source changes clear or rebase state. The stable content container, not the transformed image, supplies drag dimensions so parent preview zoom does not change drag sensitivity. Mouse left-drag pans; right/middle buttons are ignored. Native non-passive wheel listener prevents scroll only while editing, supports delta modes, and leaves Ctrl/Meta-wheel to the browser. Editing off leaves native touch/scroll behavior. Scaling remains40–100% safe contain-fit, anchored by current alignment (not arbitrary pinch focal point), with fixed header/margins; no oversize clipping. Existing sliders, reset, persistence and print geometry remain the same.

Validation:249 tests/typecheck/build pass; Chromium component harness with CDP touch verified two-touch pinch, actual mouse wheel/mouse drag and wheel disabled behavior without page errors. Synthetic component test, not physical Android/iOS hardware or live auth/printing validation.

### Visible drag/resize selection
Placement editing now displays the actual contain-fitted image bounds (not the entire available content area) with eight edge/corner resize buttons. Buttons resize proportionally and keep the opposite edge/corner where possible, clamping at safe scale/margins. Edge handles also preserve aspect ratio; they do not stretch only one dimension. Handles support pointer/touch and arrow keys, remain inside the content bounds and are excluded from print. Pointer mode tracks whether drag began on a handle; transition to pinch or back to a single pointer rebases cleanly. Ordinary interior dragging pans; scaling, presets and drafts continue using existing Placement fields. Full-fit no-slack behavior is intentional, not a promise of free off-page drag. Explicit 'make room to move' button sets scale85% without silently changing print state on entering edit mode.

### Independent edge stretch and header spacing
Edge handles now resize only one axis (N/S height, E/W width). Opposite edge remains fixed where safe bounds allow; corners scale both axes together while preserving the current shape, not necessarily the original aspect if already stretched. Width/height stretch factors (0.4–3, default1) persist with PageEdit and remain clamped to content area. Auto Fit resets stretches to1. This is raster stretching: text/table proportions change; it does not move just a table or reflow individual questions. Header/source pixels are unchanged. Image geometry and selection use one shared placementSize function for print/screen/drag.

Ready header controls add line on/off for the generated simple/custom header divider and a0–15mm gap slider, default2mm. Existing source-PDF lines and branded note boxes are not removed. These settings are saved in explicit local user drafts with finite bounded restoration; they do not alter shared account header template schema or admin source presets. Shorter generated-header bottom padding avoids extra artificial gap; source-internal whitespace still needs crop. First-selected-page-only behavior unchanged.

Verification:252 tests/typecheck/build; Chromium component harness checks bottom-handle stretch keeps top and width fixed while increasing height, generated header line hides, gap equals2mm, and one A4 sheet still prints as one page. Not physical device/live auth validation.
