## Optional light-blue watermark reduction
Per-page `blueWatermark` strength (0–1, default 0 for existing drafts/presets) runs on fresh raster pixels **before** grayscale/BW. Conservative light-blue/cyan selection fades matching pixels toward white; dark/neutral ink and other hues are not targeted. It can also remove legitimate light-blue diagrams/text. No semantic distinction between watermark and colored content, no PDF-object deletion, no recovery of obscured text and no guarantee of total removal. Original comparison, undo/redo/reset, local drafts, admin shared presets and print rendering use the same existing edit pipeline. Only use on documents with modification rights. Never enable globally or silently on all pages.

Supplied 9-page ICT PDF was tested locally on page 2 using a white-background raster. At full strength 74,065 pixels changed at 2x raster scale. Visual review showed the large blue lettering substantially reduced, but gray outlines and red/gray marks remain. Not a claim of complete removal or proof every question is intact. A review PNG is outside the repository; the source PDF is not seeded, published or uploaded to storage. Browser PDF.js rendering may differ from this local MuPDF sample; users must review the actual studio print preview.

The browser uses existing PDF.js to render that ORIGINAL source page (not an edited image), reads Bengali+English in a Web Worker, submits bounded text/confidence with matching page+lease, then the server calls DeepSeek. One page per receipt is leased at a time; provider submissions are single-use, bounded to three attempts per page, and never debit the paper wallet again. Local OCR failures mark error and can retry; interrupted/abandoned leases recover after10minutes. Revisit resumes pending pages and reuses saved results. No promise of work continuing while the tab is closed.

**Trust boundary:** browser OCR is inherently client-supplied/unverified. Ownership/page/lease enforcement limits entitlement and provider costs but CANNOT prove that submitted OCR text/confidence really came from the PDF. Results are owner-private drafts, never approved answer-bank data. An authenticated owner can tamper with their own OCR payload; do not treat it as authoritative source evidence. Text is bounded60k characters and sent as untrusted quoted input. Prompt injection and model errors are not eliminated.

Superseded all-page gate: see the question-scoped OCR fix below. OCR confidence is not fidelity verification; Bangla fonts, mathematics, columns and diagrams are major limitations. DeepSeek is instructed not to infer diagrams/graphs/geometry or unavailable table layout. Every OCR result is marked incomplete; it cannot prove that every printed question was read.

MCQ/SQ/CQ answers are validated; model low/unknown confidence, unreadable questions, duplicate identifiers and malformed MCQ labels are blank. Truncated responses fail safely. All OCR results are marked incomplete because OCR cannot establish that every printed question was captured. Self-reported confidence is **not correctness verification**; even retained drafts can be wrong. AI printouts explicitly require verification. Prior already-completed AI drafts are preserved, not regenerated automatically. Source context is limited to one page; no guessed continuations.

This is a browser-driven resumable worker, **not a durable background queue**. While the paid studio is open it processes pages sequentially; closing the tab may interrupt work. Reopening the saved purchase retrieves persisted results, recovers expired leases after ten minutes and resumes pending pages without another question-paper charge. Transport failures require Retry. Done pages with unsolved blanks are intentionally not regenerated. No live provider generation has been verified with real browser OCR + a live provider; mocked provider/security checks are not a real payment/provider end-to-end test.

## Question-scoped OCR fix and actual blank retry

The earlier all-page confidence gate suppressed valid model answers whenever **any** word was weak. It is removed. Browser OCR now keeps original line order and replaces individual words scoring below45 with `[UNCLEAR]`, submitting `scoped:true`. Page-average confidence/uncertain alone never erases other clear questions. DeepSeek must return verbatim contiguous `evidence` covering the entire question and MCQ options; server checks its presence in the OCR, requires no `[UNCLEAR]` in that span/quote, and still applies readable/high-confidence/MCQ-label validation. Older unscoped clients are not silently treated as safe. This is a grounding check, NOT semantic verification: OCR and model may both be wrong, evidence completeness/options/layout cannot be guaranteed. Owner-supplied OCR remains untrusted. No new vision capability is implied.

Every unanswered new draft gets a visible blank reason; printed blanks include it. UI counts retained answers and explicitly says these are attempted results, not completed solutions. A separate **ফাঁকা উত্তর আবার চেষ্টা করুন** triggers real fresh OCR/provider work for done pages with blanks, at most two extra cycles per page. Old zero-answer receipts qualify without repurchase. Existing nonempty answers are retained by printed question identifier while missing answers can be filled. Retry uses the same owner/page/single-use lease rules and never calls billing debit. Original failure attempts remain bounded; provider usage can still cost the site owner. Reload/view does not automatically rerun completed pages.

## Admin Delete

Each management row has an explicit confirmed Delete button affecting only that part, not all siblings in a split group. The ADMIN-only action validates UUID, stores `deletedAt` plus `published:false`, and invalidates library/admin/detail paths. Both public and admin library enumeration exclude archived rows. Updating an archived record via normal publish/preset action is rejected. Source Setting, original Blob, presets, receipts and saved AI results remain for existing owners; saved purchase links continue using the unpublished-owner exception. This is a recoverable soft deletion, NOT secure erasure or Blob storage cleanup. Existing public Blob links are not revoked. No actual production records were deleted during development.
