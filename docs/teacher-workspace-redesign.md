# Teacher workspace dashboard redesign

User supplied eight reference screenshots (wallet/recharge, header apps/profile menus, app tiles and dark welcome dashboard). New /dashboard combines these patterns under QuestionMakerBd branding: compact account header with real balance, recharge, native apps/profile disclosures; dark navy/green greeting card with user name, optional institution, create/package CTAs; actual saved/English draft counts, active package + expiry; six card shortcuts and own paid-question count. Responsive two/three column cards and stacked mobile stats. No copied identities, balances, free-paper counts or competitor price policies.

All authenticated roles including default Google STUDENT receive the creator workspace (no role elevation). Teacher/ADMIN institution editing still uses existing onboarding through ?edit=1; automatic onboarding interruption removed. ADMIN link conditionally shown from database role. Student model-test shortcut retained; old student feed/blog dashboard presentation replaced intentionally. No OMR routes implemented, so no dead OMR claims/cards. Profile editing remains /profile, package details /packages. Dashboard auth resolves account by session ID rather than email.

/wallet redesigned with same shell, balance/real rates/package cards, existing Send Money number01773729897 and bKash/Nagad only, clipboard copy with failure feedback, min20 reminder, unchanged manual approval form plus amount presets. Actual per-user recharge and question receipt tables, empty/load-failure states and horizontal table scroll. No invented running-balance ledger: existing records do not store historical resulting balances. No promise of free remaining papers. At most50 records displayed; sorting of the retrieved subset by record date is presentation only, not a guarantee of latest50 across all records. Invalid JSON skipped and invalid date/amount rendered as unavailable. Clipboard requires browser permission/secure context.

workspaceSummary uses only current user's ID, own qbpaper/English hashed owner/purchased prefixes and APPROVED, unexpired package. Package errors remain undefined, distinct from no active package; count/balance errors show unavailable rather than misleading zero. Existing ensureWallet can provision the already-supported one-time20 bonus; no change in bonus/checkout/recharge/role rules. Shared global chrome hidden on /wallet just as /dashboard to prevent duplicates. Older DashHome/DashShell components retained unused for historical compatibility, not deleted. Header dropdowns close on outside pointer/Escape and keyboard summary works natively. No focus trap as these are nonmodal menus.
